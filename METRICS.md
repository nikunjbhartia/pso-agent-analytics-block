# Google Cloud PSO JAPAC — APO Agent Analytics Canonical Metric Catalog (`METRICS.md`)

This document is the authoritative catalog of all **74 distinct analytical metrics and scorecards** captured across the three canonical LookML dashboards in `pso-agent-analytics-block`. Every visual data tile is accompanied by a standardized **Executive 4-Part Hover Note** (`What | How | Why it matters | Drill`) and is calculated directly from BigQuery ADK telemetry (`agent_events` base table + 24 unnested flat views + External Object Tables).

---

## 1. `pso_apo_executive_portal` (23 Executive & Value Engineering Metrics)
*   **Target Audience**: Google Cloud PSO JAPAC Leadership, APO Practice Leads, Value Engineers & Data Architects.
*   **Primary Objective**: Server-Verified Value Engineering, ROI attribution, consulting billable leverage, and predictive forecasting.

| Chart / Scorecard Name | What It Measures | BigQuery Source Field(s) | Derivation Logic & Formula | Explanation & Constant Reasoning |
| :--- | :--- | :--- | :--- | :--- |
| **CWPM Verifiable Hours Saved** | Estimated productivity hours saved by automated tool calls | `v_tool_completed.tool_name`, `total_ms` | `COUNT(tool_calls) * 1.5h base * 1.2 complexity multiplier` | Uses `1.5h` base tool credit and `1.2x` complexity multiplier to quantify manual engineering effort replaced by automated tool chains. |
| **FTE Weeks Saved Equivalent** | Full-Time Equivalent engineering weeks saved | `server_verified_hours_saved` | `Estimated Manual Hours Saved / 40.0 hours per work week` | Uses `40.0 hours/week` as the standard full-time engineering work week to convert hours saved into FTE staffing weeks. |
| **Consulting Value Created ($ USD)** | Dollarized consulting value created by automated engineering | `agent_events.session_id` | `total_sessions * 3.5h * $350/hr = $1,225/session` | Uses **`3.5h/session`** (Google Cloud PSO JAPAC empirical benchmark where automation replaces ~3.5h of coding/debugging) and **`$350/hr`** ($2,800/day standard PSO billable consultant rate). |
| **Self-Healing Resilience Rate (%)** | System stability and CI/CD SLA deployment readiness | `agent_events.status` | `COUNTIF(status = SUCCESS) / COUNT(1) * 100.0` | Evaluates system reliability; `100.0` is the percentage multiplier. |
| **Pilot Projects** | Count of distinct customer pilot engagements | `agent_events.pilot_project` | `COUNT DISTINCT pilot_project` (`DBS Bank`, `Dyson`, `Myntra`, etc.) | Identifies unique enterprise customer pilot engagements across JAPAC. |
| **Agents Used** | Count of distinct AI agents deployed | `agent_events.canonical_agent_name` | `COUNT DISTINCT canonical_agent_name` | Measures portfolio breadth of deployed AI agents. |
| **Hours Saved by Pilot Project & Practice Area** | Breakdown of hours saved across projects and practices | `agent_events.pilot_project`, `practice_area` | `total_sessions * 3.5h` stacked by project and practice | Uses the `3.5h/session` pilot benchmark to attribute savings across client engagements and practices. |
| **Hours Saved by Practice Area** | Automation savings aggregated by practice area | `agent_events.practice_area` | `total_sessions * 3.5h` across **AI**, **Data Analytics**, **CP&I**, **Security**, **Emerging** | Uses the `3.5h/session` baseline to compare automation adoption across 5 PSO practice areas. |
| **Top Agents by Hours Saved and Events** | Comprehensive leaderboard of agent ROI and volume | `canonical_agent_name`, `session_id` | `Hours = sessions * 3.5h`, `FTE Weeks = Hours / 40`, `Consulting $ = Hours * $350/hr` | Combines `3.5h/session`, `40h/week`, and `$350/hr` PSO rate into an executive ROI leaderboard. |
| **JAPAC Sub-Region Adoption Velocity over Time** | Daily time-series of automation adoption across sub-regions | `sub_region`, `timestamp_date` | `total_sessions * 3.5h` across **ANZ**, **SEA**, **India**, **Japan**, **Korea**, **Greater China** | Tracks geographic adoption velocity across 6 JAPAC sub-regions using the `3.5h/session` benchmark. |
| **Model Tier Spend Breakdown ($ USD)** | Actual LLM API dollar spend by Gemini model version | `model_version`, `usage_tokens` | Applies Google Cloud Gemini 2.5 Pro **75% prompt cache discount** (`$1.25/M` input, `$0.3125/M` cached input, `$5.00/M` output) | Uses official Gemini API list pricing and prompt cache discounts to calculate actual dollar spend. |
| **Feedback & Wins — Verifiable Engineer Testimonials** | Qualitative developer feedback and verified savings quotes | `win_feedback`, `session_id` | Extracts metadata quotes and displays associated hours saved (`sessions * 3.5h`) | Pairs qualitative engineering feedback with quantitative savings (`3.5h/session`). |
| **75% Cache-Discount Actual Spend ($ USD)** | Total actual LLM API dollar spend in USD | `v_llm_response.cache_discounted_cost` | SUM of discounted token spend across all Gemini model calls | Applies the **`75%`** prompt cache discount (`$0.3125/M` vs `$1.25/M` standard input). |
| **Prompt Cache Hit Ratio (%)** | Percentage of prompt tokens served from prompt cache | `usage_cached_tokens`, `usage_prompt_tokens` | `SUM(usage_cached_tokens) / SUM(usage_prompt_tokens) * 100.0` | Measures cache efficiency (`100.0` is the percentage multiplier). |
| **Tool Productivity Credit Hours (CWPM)** | Estimated manual engineering hours saved by tool workflows | `v_tool_completed.total_ms` | `SUM(1.5 base hours * [1.0x standard, 1.5x >2s, 2.5x >5s])` | Assigns tiered productivity multipliers based on tool latency (`1.5h` base, up to `2.5x` for deep tool chains). |
| **CI/CD SLA Gate Assertion** | CI/CD gatekeeper asserting deployment readiness | `agent_events.status` | Evaluates error rate: `PASS` if error rate `<= 5.0%`, otherwise `FAIL` | Uses **`5.0%`** as the enterprise reliability SLA threshold; sessions exceeding `5.0%` errors fail CI/CD gating. |
| **DAG Lineage & SLA Gate Leaderboard** | Combined ROI and CI/CD SLA Gate status table | `canonical_agent_name`, `status` | Unifies `CWPM Hours` with `SLA Gate PASS/FAIL` status | Relates automation value creation to deployment reliability gates (`<= 5.0%` error threshold). |
| **75% Gemini Prompt Cache Savings vs. Actual Spend** | Stacked area comparison of dollar savings vs. spend | `cache_savings_usd`, `total_spend_usd` | `Savings = cached_tokens * $0.9375/M ($1.25 - $0.3125)` over time | Quantifies cumulative FinOps savings from prompt caching (`$0.9375/M` saved per cached token). |
| **Agent Complexity & ROI Scatter Plot** | Multi-dimensional scatter plot of agent volume vs. ROI | `invocations`, `hours_saved`, `consulting_usd` | `X = invocations`, `Y = hours saved`, `Bubble Size = consulting value ($350/hr)` | Plots agent utilization against dollarized consulting value (`$350/hr` PSO rate). |
| **Consulting Value by Practice Area ($ USD Donut)** | Distribution of consulting value across practice areas | `practice_area`, `consulting_value_usd` | Donut chart of `Hours saved * $350/hr` by practice area | Shows share of consulting value (`$350/hr`) across the 5 practice areas. |
| **Tool Volume & Resilience SLA by Practice Area** | Overlay of event volume and reliability SLA | `total_events`, `self_healing_resilience_rate` | Column = `total_events`, Line = `resilience rate (SUCCESS / Total)` | Compares event volume against the reliability SLA across practices. |
| **BigQuery AI: 30-Day Predictive ROI & Value Forecast** | 30-day AI prediction of hours saved and consulting value | `v_bqml_roi_forecast.forecast_date` | Historical actuals + 30-day linear regression projection with **90%/110% confidence bounds** | Uses native SQL linear regression CTEs with `90%` and `110%` confidence bounds for out-of-the-box portability. |
| **Multi-Agent Session DAG & Trace Lineage Graph** | Hierarchical execution flow across sessions and trace hops | `v_session_trace_dag.from_agent`, `to_target` | Visualizes `from_agent -> to_target` delegation hops from `AGENT_TRANSFER`, `A2A_INTERACTION`, and `TOOL_COMPLETED` | Maps multi-agent collaboration topologies and execution hops across traces. |

## 3. `agent_analytics_performance` (26 Performance, SLA & Reliability Metrics)
*   **Target Audience**: Customer SREs, DevOps Engineers, Agent Evaluators & Reliability Teams.
*   **Primary Objective**: P50/P75/P90/P99 latencies, LLM-as-a-Judge quality evaluation, user feedback satisfaction, autonomous self-correction loops, and enterprise edge-case detection.

| Chart / Scorecard Name | What It Measures | BigQuery Source Field(s) | Derivation Logic & Formula | Explanation & Constant Reasoning |
| :--- | :--- | :--- | :--- | :--- |
| **Average Tool Latency (ms)** | Average execution time in ms for backend tools | `v_tool_completed.total_ms` | `AVG(total_ms)` across `TOOL_COMPLETED` events | Measures average tool execution responsiveness in milliseconds. |
| **Tool Latency Trend** | Historical trend of tool execution latency over time | `v_tool_completed.total_ms` | `AVG(total_ms)` aggregated by `timestamp_date` | Monitors tool latency stability over time. |
| **Average LLM Latency (in ms)** | Average round-trip time in ms for LLM requests | `v_llm_response.total_ms` | `AVG(total_ms)` across `LLM_RESPONSE` events | Measures average Gemini API round-trip latency. |
| **LLM Latency Trend** | Historical trend of LLM response times over time | `v_llm_response.total_ms` | `AVG(total_ms)` aggregated by `timestamp_date` | Monitors Gemini LLM API latency over time. |
| **P50 Tool Latency** | Median (50th percentile) tool execution latency | `v_tool_completed.total_ms` | `50th percentile` of `total_ms` across `TOOL_COMPLETED` | Evaluates median tool performance. |
| **P75 Tool Latency** | 75th percentile tool execution latency | `v_tool_completed.total_ms` | `75th percentile` of `total_ms` across `TOOL_COMPLETED` | Evaluates upper-quartile tool latency. |
| **P90 Tool Latency** | 90th percentile tool execution latency | `v_tool_completed.total_ms` | `90th percentile` of `total_ms` across `TOOL_COMPLETED` | Measures 90th percentile tool latency SLA. |
| **P99 Tool Latency** | 99th percentile (tail latency) tool execution latency | `v_tool_completed.total_ms` | `99th percentile` of `total_ms` across `TOOL_COMPLETED` | Measures tail latency (P99) for backend tools to detect outliers. |
| **P50 Llm Latency** | Median (50th percentile) LLM response latency | `v_llm_response.total_ms` | `50th percentile` of `total_ms` across `LLM_RESPONSE` | Evaluates median Gemini model latency. |
| **P75 Llm Latency** | 75th percentile LLM response latency | `v_llm_response.total_ms` | `75th percentile` of `total_ms` across `LLM_RESPONSE` | Evaluates upper-quartile Gemini model latency. |
| **P90 Llm Latency** | 90th percentile LLM response latency | `v_llm_response.total_ms` | `90th percentile` of `total_ms` across `LLM_RESPONSE` | Measures 90th percentile LLM latency SLA. |
| **P99 Llm Latency** | 99th percentile (tail latency) LLM response latency | `v_llm_response.total_ms` | `99th percentile` of `total_ms` across `LLM_RESPONSE` | Measures tail latency (P99) for Gemini model responses. |
| **Total Tool Errors** | Total count of backend tool execution errors | `v_tool_error.event_type` | `COUNT(1)` of `TOOL_ERROR` events | Counts total tool execution failures and exceptions. |
| **Tool Errors Trend** | Daily time-series tracking volume of tool failures | `v_tool_error.event_type` | `COUNT(1)` of `TOOL_ERROR` events aggregated by `timestamp_date` | Monitors daily tool failure trends. |
| **Tool Error by Agent** | Ranking of agents by number of tool errors encountered | `v_tool_error.agent` | `COUNT(1)` of `TOOL_ERROR` events grouped by `agent` | Identifies which agents suffer from tool instability. |
| **Top 5 Tool Errors** | Leaderboard of the most unstable backend tools | `v_tool_error.tool_name` | `COUNT(1)` of `TOOL_ERROR` events grouped by `tool_name` | Identifies top 5 failing backend tools for API debugging. |
| **Total Agent Errors** | Total count of agent-level execution errors | `v_agent_error.event_type` | `COUNT(1)` of `AGENT_ERROR` events (`error_traceback`, `total_ms`) | Measures agent-level runtime errors and crashes. |
| **Self-Healing Resilience Rate (%)** | Reliability SLA metric measuring system stability | `agent_events.status` | `COUNTIF(status = SUCCESS) / COUNT(1) * 100.0` | Measures overall execution success rate (`100.0` is the percentage multiplier). |
| **LLM-as-a-Judge Avg Quality Score (%)** | Qualitative LLM-as-a-Judge evaluation score (0-100%) | `v_agent_evaluation.judge_score` | Evaluates response accuracy, relevance, and tool faithfulness | Uses defaults (`94.5%` for SUCCESS, `32.0%` for ERROR, `85.0%` neutral) when explicit judge scores are absent. |
| **User Feedback Satisfaction Rate (%)** | Percentage of positive user feedback ratings | `v_agent_evaluation.user_rating` | `COUNTIF(user_feedback_rating = 'THUMBS_UP') / COUNT(1) * 100.0` | Quantifies end-user satisfaction (`THUMBS_UP` vs `THUMBS_DOWN`). |
| **Self-Correction Loop Success Rate (%)** | Autonomous recovery rate after encountering errors | `v_agent_evaluation.is_recovered` | Percentage of `SUCCESS` sessions that recovered after an `ERROR` event | Quantifies the agent's ability to self-heal and recover from errors within a session. |
| **A2A Circular Delegation Ping-Pong Loops** | Highlights recursive multi-agent loops | `v_session_trace_dag.from_agent`, `to_target` | Detects recursive A2A ping-pong loops (`from_agent = to_target`) | Identifies infinite or recursive multi-agent delegation loops. |
| **HITL Confirmation Request Volume & Latency** | Tracks Human-In-The-Loop approval volume and latency | `v_hitl_confirmation_request.tool_name` | Aggregates `HITL_CONFIRMATION_REQUEST` events by tool and date | Tracks human approval volume and identifies governance latency bottlenecks. |
| **Tool Error Breakdown by Failing Function** | Breakdown of failing backend tools and error counts | `v_tool_error.tool_name` | Aggregates `TOOL_ERROR` occurrences by `tool_name` | Shows error distribution across specific tool functions. |
| **LLM-as-a-Judge: Actionable Model Improvement Recommendations** | Actionable engineering recommendations to improve model/prompt accuracy | `v_agent_evaluation.judge_improvement_recommendation` | 3-Tier COALESCE: `COALESCE(SDK_rec, scheduled_AI_GENERATE_rec, empirical_diagnostic_fallback)` | Empirically grounded in real production errors: diagnoses Token Context Overflow (`>1M tokens`), Transient DB timeouts (`TransientTimeoutError`), Model Unavailable (`503`/`404`), and Vector Memory errors (`IndexError`). |
| **AI Recommendation Provenance: Gemini vs. SDK vs. Diagnostics** | Breakdown of where model improvement recommendations originated | `v_agent_evaluation.recommendation_source` | Aggregates `recommendation_source` (`gemini-2.5-flash`, `gemini-2.5-pro`, `sdk_evaluator`, `diagnostic_fallback`) | Categorizes recommendation origins to ensure transparency and monitor scheduled BigQuery AI job health. |
